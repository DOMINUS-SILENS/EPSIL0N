## Objective

Improve PostgreSqlEventStore error messages to provide full operational context:
- Include tenant ID and stream ID in all error messages
- Preserve causation/correlation chains from event metadata
- Distinguish append vs load operation failures
- Wrap database-specific errors with appropriate EventStoreException subclasses
- Ensure unexpected errors still propagate with original exception context

## Why This Matters

Current error handling is incomplete:
- `load()` and `loadReverse()` have NO error handling for database failures
- `performAppend()` wraps generic database errors without tenant/operation context
- Unexpected errors throw RuntimeException instead of EventStoreException
- Error messages lack stream metadata needed for debugging

This makes it difficult to trace event store failures back to specific aggregates and tenants.

## Current State

- `getStreamVersion()` — No error handling
- `load()` — No error handling
- `loadReverse()` — No error handling
- `performAppend()` — Partial error handling, generic messages
- `validateExpectedVersion()` — Version conflicts don't preserve previous exception
