## Architecture Principles (From OOD Analysis)

### Why ES + CQRS is Ideal for Offline Mobile

1. **Events are immutable** — Safe to store and replay offline
2. **Append-only** — No updates to conflict, only new events
3. **Vector clock friendly** — Events naturally track causality
4. **Reconciliation possible** — Merge offline events with server state

### Anti-Patterns to Avoid

| Anti-Pattern | Why | Solution |
|--------------|-----|----------|
| Sync entire aggregates | Bandwidth waste | Sync events only |
| Timestamp ordering | Clock drift | Use SyncVersion (vector clock) |
| Silent conflict resolution | Data loss | Surface to user or use merge strategy |
| Unencrypted tenant on device | Security risk | Encrypt tenant context |

## Optimal Component Design

### 1. DeviceId — First-Class Primitive

```php
// packages/kernel/src/Domain/Identity/DeviceId.php
final class DeviceId extends ValueObject
{
    public static function generate(): self;
    public static function fromString(string $id): self;
    public function toString(): string;
}
```

**Why:** DeviceId must be first-class like TenantId for:
- Audit trails (which device made changes)
- Conflict resolution (device priority)
- Tenant-device mapping

### 2. SyncVersion — Vector Clock / HLC

```php
// packages/kernel/src/Domain/Sync/SyncVersion.php
final class SyncVersion
{
    public static function initial(): self;
    public static function fromVectorClock(array $clock): self;
    
    // Increment for local event
    public function increment(DeviceId $device): self;
    
    // Merge with server version
    public function merge(self $other): self;
    
    // Compare versions
    public function happensBefore(self $other): bool;
    public function isConcurrentWith(self $other): bool;
    
    public function toArray(): array; // For serialization
}
```

**Why:** Simple int sync_id has issues:
- Can't detect concurrent edits
- Can't merge diverged states
- Clock skew causes ordering issues

**Vector Clock Properties:**
- `A happensBefore B` — A happened before B
- `A isConcurrentWith B` — Concurrent edits, need merge

## Sync Protocol (Optimized)

```
┌─────────────────────────────────────────────────────────────┐
│                    OFFLINE PHASE                            │
├─────────────────────────────────────────────────────────────┤
│ 1. User action generates DomainEvent                        │
│ 2. Attach DeviceId + SyncVersion (increment)               │
│ 3. Store in local queue with status='pending'              │
│ 4. Continue offline (no server contact)                     │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                    RECONNECT PHASE                          │
├─────────────────────────────────────────────────────────────┤
│ 1. Send pending events + local SyncVersion                 │
│ 2. Server merges with its version vector                   │
│ 3. Check for concurrent edits (syncVersion.isConcurrent)   │
│ 4. Apply conflict resolution strategy                     │
│ 5. Return new server SyncVersion + results                 │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                    SYNC PHASE                              │
├─────────────────────────────────────────────────────────────┤
│ 1. Client receives reconciled version                       │
│ 2. Update local SyncVersion (merge)                        │
│ 3. Pull deltas from ISyncProjection.getDeltaSince()        │
│ 4. Update local state from deltas                          │
└─────────────────────────────────────────────────────────────┘
```

## Database Schema (Complete)

```sql
-- Device registry
CREATE TABLE sync_devices (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID NOT NULL,
    device_id       VARCHAR(255) NOT NULL,
    device_type     VARCHAR(50) NOT NULL, -- ios, android, web
    sync_version    JSONB NOT NULL DEFAULT '{}',
    last_sync_at    TIMESTAMP,
    created_at      TIMESTAMP NOT NULL DEFAULT NOW(),
    UNIQUE(tenant_id, device_id)
);

-- Pending event queue with vector clock
CREATE TABLE pending_event_queue (
    id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    device_id           VARCHAR(255) NOT NULL,
    aggregate_id        VARCHAR(255) NOT NULL,
    aggregate_type      VARCHAR(100) NOT NULL,
    event_type          VARCHAR(100) NOT NULL,
    event_payload       JSONB NOT NULL,
    sync_version        JSONB NOT NULL,
    correlation_id      UUID NOT NULL,
    causation_id        UUID NOT NULL,
    offline_created_at  TIMESTAMP NOT NULL,
    server_version      JSONB NULL,
    created_at          TIMESTAMP NOT NULL DEFAULT NOW(),
    status              VARCHAR(20) DEFAULT 'pending',
    retry_count         INTEGER DEFAULT 0,
    UNIQUE(device_id, correlation_id)
);

-- Queue replay log
CREATE TABLE queue_replay_log (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    device_id       VARCHAR(255) NOT NULL,
    correlation_id  UUID NOT NULL,
    status          VARCHAR(20) NOT NULL,
    conflict_type   VARCHAR(50),
    error_message   TEXT,
    replayed_at     TIMESTAMP NOT NULL DEFAULT NOW()
);

-- Indexes
CREATE INDEX idx_devices_tenant ON sync_devices(tenant_id);
CREATE INDEX idx_pending_queue_device_status ON pending_event_queue(device_id, status, created_at);
CREATE INDEX idx_replay_log_device ON queue_replay_log(device_id, replayed_at);
```
